# 有 root 的自动注入 + 网页开关（对应 yhjmew.no.ore.ui / No OreUI）

## 一、那个仓库是怎么实现的

`yinghuajimew/yhjmew.no.ore.ui`（No OreUI）**不是**注入工具，它是个「改包器」：手机上把官方
Minecraft 基岩版 APK 拆开、塞东西、再重新签名。四步在 `app/src/main/java/yhjmew/no/ore/ui/ApkProcessor.java`：

1. **读**：从 APK 读 `AndroidManifest.xml`、`resources.arsc`、所有 `classes*.dex`。
2. **改写**：
   - 找到含 `Lcom/mojang/minecraftpe/MainActivity;` 的 dex，在 `MainActivity.onCreate` 指令最前面插一条
     `invoke-static {p0}, Lcom/mojang/minecraftpe/SoLoader;->loadLibrary(Landroid/content/Context;)V`，
     插完把所有 try/catch 地址统一 `+3`（`CODE_UNIT_SHIFT = 3`），并用 `alreadyInjectedLoadLibrary()` 防重复插。
   - 追加 `inject_classes.dex`（`dev.yejdhi.loader.*` + `com.mojang.minecraftpe.SoLoader` → `System.loadLibrary("ForceCloseOreUI")`）。
   - 追加 `lib/arm64-v8a/libForceCloseOreUI.so`（ZIP 里 STORED 不压缩 + 4K 对齐），可选 `libpreloader.so`。
   - 共存模式再改包名和 `resources.arsc`（`ManifestPatcher.patchResourcesArsc`）。
3. **签名**：v2/v3 重签（`SignatureManager`，内置 apksig）。
4. **规整**：条目时间戳钉死 2008-01-01，`alignTo4K` 做 16KB 页对齐（天玑 9400+ 之类新设备）。

真正干活的 so 在 `ForceCloseOreUI-android/src/ForceCloseOreUI.cpp`：

- `__attribute__((constructor))` → 起后台线程；
- 读 `/proc/self/maps` 找 `libminecraftpe.so` 的所有 `r-x` 段（`extractNativeLibs=false` 时兜底扫 base.apk 大段）；
- 段内**内存特征码扫描**定位 oreUI 配置函数（`detour_v1` / `detour_v10` 两套签名）；
- `DobbyHook` 挂上，detour 里 **先 applyConfig → 调原函数 → 再 applyConfig**（先让原函数以「禁用」状态跑，再补一遍防它重建 `mConfigs`）；
- `applyConfig` 就是按界面区域（`play` / `settings` / `achievement` …）往 `std::unordered_map mConfigs` 写值，数据来自
  `/storage/emulated/0/Android/data/<pkg>/mods/ForceCloseOreUI/config.json`；
- 自带崩溃处理器（`crash_native.log`）和 logcat 抓取线程。

**一句话：改包只是为了让这个 so 被 `System.loadLibrary` 加载；关 oreUI 全是运行时内存操作。**

## 二、有 root 为什么可以不改包

改包的代价：签名变了（登录态、成就、内购、部分联机服务出问题），每次游戏更新都要重打重下。
有 root 就换成：**包一个字不动，等进程起来、引擎 so 已映射后，ptrace 直接把同一个 payload 塞进去**，
游戏看到的还是官方签名。

```
开机 → service.sh 守着一个 WebUI（127.0.0.1:8899）
     → 你在页面点开关 / 或 AUTO_INJECT=1
     → 找 pid → 等 libminecraftpe.so → payload 复制进游戏私有目录
     → fcou-inject：ptrace 远程 dlopen(payload) → payload 自己挂钩关闭 oreUI
```

## 三、包里有什么

```
fcou_autoinject-v1.1.zip
├── module.prop / post-fs-data.sh
├── service.sh            守护：拉起 WebUI；AUTO_INJECT=1 时顺手自动注入
├── settings.conf         PKG / AUTO_INJECT / WEBUI_PORT / RETRY / WAIT_ENGINE_S / SKIP_ENGINE_WAIT
├── inject-now.sh         命令行注入一次（= fcou-inject --once）
├── webui-start.sh        手动起 WebUI
├── webroot/index.html    KernelSU 模块 WebUI 页面（用 ksu.exec 直接执行，不依赖端口）
├── bin/fcou-inject       aarch64 静态注入器 + 内置 HTTP 服务（musl 静态，134KB）
├── payload/libForceCloseOreUI.so   就是 No OreUI 里那个 standalone payload（Dobby 版）
└── src-fcou-inject.c     注入器/WebUI 源码
```

### WebUI

内置 HTTP 服务，只监听 `127.0.0.1`（默认 8899）。浏览器打开 `http://127.0.0.1:8899`：

- 三行状态：游戏进程 PID / `libminecraftpe.so` 是否加载 / payload 是否已注入；
- 大开关 **「注入并关闭 oreUI」**：点开 → 跑完整注入流程 → 页面直接回显日志；
  开关只能开不能关（注入是进程级的，想恢复就重启游戏）；
- 小开关 **「开机自动注入」**：直接改写 `settings.conf` 里的 `AUTO_INJECT`，守护循环下一轮就读到，不用重启；
- 接口：`GET /`、`GET /api/status`、`POST /api/inject`、`POST /api/auto?on=1`、`GET /api/log`。

KernelSU 用户不用浏览器：模块详情里「打开 WebUI」就是 `webroot/index.html`，它用 `ksu.exec` 调
`bin/fcou-inject --once`，同一套开关；没有 ksu 桥接时会提示去开 8899 那个页面。

### 注入器怎么工作（`src-fcou-inject.c`）

1. `PTRACE_ATTACH` 游戏主线程，`PTRACE_GETREGSET(NT_PRSTATUS)` 保存 31 个通用寄存器 + sp/pc/pstate；
2. 在目标 `libc.so` 的 `r-x` 段里找 `svc #0; ret`（`01 00 00 D4 C0 03 5F D6`）当远程 syscall 小工具；
3. 远程 `mmap`（`__NR_mmap` = 222）拿一页 RW，写入 payload 绝对路径；
4. 在目标 `libdl.so` / `libc.so` / `linker64` 里**按内存 ELF 解析**出 `dlopen`（PT_DYNAMIC → DT_SYMTAB/DT_STRTAB + load_bias 修正）；
5. `pc = dlopen`、`lr = 0` 跑一次：payload 构造函数在游戏进程里执行；返回时 `ret` 跳到 0 触发 `SIGSEGV(pc==0)`，
   此时 `x0` 就是返回值；
6. **恢复寄存器 → `PTRACE_CONT` 放行 → 注入器退出**（内核自动 detach）。

### 那个坑：不能在 SIGSEGV stop 上直接 DETACH

第一版是「恢复寄存器 → `PTRACE_DETACH`」，目标必崩：从同步缺页的 signal-delivery-stop 上 detach，内核会重放那条缺页指令。
改成本机实测通过的写法后：注入成功、目标存活、重复执行自动跳过、路径不存在时干净失败不伤目标。

```
svc gadget @ 0x72e6dc2148
dlopen @ 0x72e6d81470 (in libc.so)
远程内存 0x72e6bf0000
dlopen 成功 handle=0x5500025270
注入成功：testpay.so 已映射进目标进程
已恢复寄存器并放行目标线程（注入器退出后内核自动 detach）
```

## 四、安装 & 用

1. 装 `fcou_autoinject-v1.1.zip`（Magisk / KernelSU 本地安装）→ 重启。
2. 浏览器打开 `http://127.0.0.1:8899`（KernelSU 就直接点「打开 WebUI」）。
3. **先开游戏、进到主菜单**，再点「注入并关闭 oreUI」；页面会打出：
   `引擎已加载 → payload 就位 → dlopen 成功 → 注入成功`。
4. 回游戏，设置界面应该已经是老 jsonUI。
5. 不想点的话，把「开机自动注入」打开（或 `settings.conf` 里 `AUTO_INJECT=1`），下次开机自己来。

命令行等价物：

```sh
su -c sh /data/adb/modules/fcou_autoinject/inject-now.sh     # 注入一次
su -c sh /data/adb/modules/fcou_autoinject/webui-start.sh     # 前台起 WebUI
su -c '/data/adb/modules/fcou_autoinject/bin/fcou-inject --status'   # 打印 JSON 状态
su -c 'tail -f /data/adb/modules/fcou_autoinject/fcou.log'
su -c 'tail -f /data/adb/modules/fcou_autoinject/webui.log'
su -c 'logcat -s ForceCloseOreUI'      # payload 自己的日志
```

## 五、配置 oreUI 开关

payload 读 `/sdcard/Android/data/com.mojang.minecraftpe/mods/ForceCloseOreUI/config.json`（没有会自动生成模板）：

```json
{ "settings": false, "play": true, "achievement": false }
```

`false` = 该界面用旧 jsonUI，`true` = 保留 oreUI；改完重启游戏生效（按 mtime/size 缓存）。

## 六、排错

| 现象 | 处理 |
|---|---|
| 页面「服务未连接」 | WebUI 没起来：`su -c sh .../webui-start.sh`，看 `webui.log`（端口被占会 bind 失败） |
| `游戏没在跑` | `PKG` 不对，或游戏没启动 |
| `等了 90s 还没看到 libminecraftpe.so` | 调大 `WAIT_ENGINE_S`；调试非 MC 目标可用 `SKIP_ENGINE_WAIT=1` |
| `dlopen 返回 NULL` | 目标读不到 so：`chown` 到游戏 uid + `chcon u:object_r:app_data_file:s0`；或依赖缺失 |
| 注入成功但界面没变 | 版本超出 payload 签名表（1.21.90 ~ 1.26.60）；换新版 `payload/libForceCloseOreUI.so`，其余不用改 |
| `PTRACE_ATTACH: Operation not permitted` | 有别的调试器/注入器占着进程，重启游戏 |
| 游戏闪退 | 看 `/sdcard/Android/data/com.mojang.minecraftpe/mods/ForceCloseOreUI/crash_native.log` |

## 七、限制

- 只支持 **arm64**；默认只针对 `com.mojang.minecraftpe`（`settings.conf` 的 `PKG` 可改，但 payload 只对 MC 有效）。
- 不要和「No OreUI 改包版」同时用，同一个 so 加载两次容易打架。
- WebUI 只监听回环地址；想局域网访问就把 `serve_forever()` 里的 `INADDR_LOOPBACK` 改成 `INADDR_ANY`（自担风险）。
- payload 是第三方闭源二进制，签名表写死；游戏更新后先看 `logcat -s ForceCloseOreUI` 有没有 `Hook installed`。
